(3) TOP 10 FAILURE MODES (RANKED)
- 1) Late/out-of-order trades assigned to wrong candle bucket. Score: Likelihood 4 × Blast Radius 5.
  - Symptom: OHLC values may be deterministic but bars land in wrong second.
  - Root cause chain: processor floors `event.ts_ms` (storage timestamp) for bucket, not `trade_ts_ms`; delayed delivery shifts trade into later bucket.
  - Code anchors: `/src/ravebear_monolith/processors/okx/trades_to_bars_1s.py:147-161`.
  - Detection: invariant check `abs(bucket_ts_ms - trade_ts_ms_floor) == 0` should hold for near-real-time stream.
  - Mitigation: bucket by `trade_ts_ms` when present; only fallback to `event.ts_ms`.
  - EVIDENCE: bucket computation line 160.
- 2) Replay with different cursor double-counts bars. Score: 4 × 5.
  - Symptom: volume/trade_count inflate after backfill/live merge or accidental re-run.
  - Root cause chain: replay reprocesses same events, `BarSink.upsert_bar()` adds volume/trade_count on conflict (not replace).
  - Anchors: `/src/ravebear_monolith/storage/bar_sink.py:127-133`; confirmed by test `/tests/test_trades_to_bars_1s_processor.py:170-179`.
  - Detection: checksum of per-second trade_count from events vs bars drifts upward after rerun.
  - Mitigation: include deterministic per-bar aggregate replacement in replay mode (replace not additive) or enforce single cursor.
  - EVIDENCE: explicit ON CONFLICT summation.
- 3) Timestamp parse fallback silently uses local wall-clock time. Score: 3 × 5.
  - Symptom: events inserted at current host time, causing replay ordering corruption and apparent data jumps.
  - Root cause chain: `EventSink._parse_timestamp` catches `ValueError` and returns `datetime.now().timestamp()` (naive local time).
  - Anchors: `/src/ravebear_monolith/storage/event_sink.py:192-203`.
  - Detection: log/metric count of parse failures; invariant `abs(parsed_ts - payload.trade_ts_ms)` threshold alarm.
  - Mitigation: fail closed on parse error or use timezone-aware UTC fallback with explicit error metric.
  - EVIDENCE: fallback branch line 203.
- 4) Seconds-vs-milliseconds mistake accepted as valid timestamp. Score: 3 × 5.
  - Symptom: timestamps near 1970 or far-future bars/events.
  - Root cause chain: `_normalize_timestamp` treats any digit string/int as milliseconds; seconds input (10 digits) is divided by 1000 again.
  - Anchors: `/src/ravebear_monolith/collectors/okx/schemas.py:81-85`.
  - Detection: reject timestamps outside expected trading epoch window.
  - Mitigation: branch by magnitude (`>=1e12` ms else seconds).
  - EVIDENCE: ms-only conversion logic.
- 5) Naive datetime interpreted in local timezone. Score: 3 × 4.
  - Symptom: DST/local timezone shift offsets event times.
  - Root cause chain: `datetime.fromisoformat()` on naive string yields naive datetime; `.timestamp()` interprets local timezone.
  - Anchors: `/src/ravebear_monolith/storage/event_sink.py:197-201` and `/src/ravebear_monolith/collectors/okx/schemas.py:88-90`.
  - Detection: invariant requiring explicit offset in every `ts_utc` string before persistence.
  - Mitigation: reject naive strings or force `timezone.utc` attachment.
  - EVIDENCE: no explicit tz enforcement before `.timestamp()` in EventSink.
- 6) Silent drop of malformed WS messages. Score: 4 × 4.
  - Symptom: pipeline stays healthy but missing trades.
  - Root cause chain: `_process_message` catches broad exceptions and logs warning; message discarded without counter/kill switch.
  - Anchors: `/src/ravebear_monolith/collectors/okx/live.py:275-290`.
  - Detection: metric for `okx_process_error` rate and expected-vs-observed trade throughput.
  - Mitigation: increment explicit drop counter and trip kill switch on sustained drop rate.
  - EVIDENCE: broad except only logs warning.
- 7) Event dedupe key can miss true duplicates across timestamp jitter. Score: 3 × 4.
  - Symptom: same exchange trade appears twice in events table if ts differs slightly.
  - Root cause chain: event id hashes `source:ts:content_hash`; duplicate payload with changed ts yields new ID.
  - Anchors: `/src/ravebear_monolith/storage/event_sink.py:183-189`.
  - Detection: compare unique `trade_id` count in payload vs event row count.
  - Mitigation: include stable venue key (`trade_id`, `inst_id`) in idempotency strategy when available.
  - EVIDENCE: id construction does not use trade_id.
- 8) Reconnect loop can hide persistent upstream outage indefinitely. Score: 4 × 3.
  - Symptom: process remains running with no incoming events.
  - Root cause chain: `_receive_loop` retries forever with backoff and no max outage guard.
  - Anchors: `/src/ravebear_monolith/collectors/okx/live.py:167-247`.
  - Detection: heartbeat metric for seconds since last event and reconnect attempt counter.
  - Mitigation: fail closed after outage threshold by triggering kill switch.
  - EVIDENCE: while-loop has no stop condition except external stop/cancel.
- 9) Clock drift/NTP mismatch affects cursor/updated timestamps and fallback times. Score: 2 × 3.
  - Symptom: non-monotonic `updated_ts_ms`, confusing restart diagnostics.
  - Root cause chain: uses host clock via `datetime.now(timezone.utc)` in cursor updates and local now in parse fallback.
  - Anchors: `/src/ravebear_monolith/storage/cursor_store.py:127`; `/src/ravebear_monolith/storage/event_sink.py:203`.
  - Detection: monotonicity check on cursor `updated_ts_ms`.
  - Mitigation: source from monotonic/UTC synchronized clock and reject backward jumps.
  - EVIDENCE: direct now() usage.
- 10) Time-domain coverage gaps not modeled (funding/leap seconds/multi-venue calendars). Score: 2 × 3.
  - Symptom: unsupported timestamp alignment requirements silently unhandled.
  - Root cause chain: only OKX trades feed and 1s bars implemented; no funding timestamp model or multi-venue calendar layer.
  - Anchors: `/src/ravebear_monolith/collectors/okx/*`, `/src/ravebear_monolith/processors/okx/trades_to_bars_1s.py`.
  - Detection: explicit capability checks in startup health.
